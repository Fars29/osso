# Osso UI — popup and options

Two static pages, vanilla TypeScript, no framework. `tokens.css` holds the palette (paper, ink, muted, line, the fade grey, marrow) with a dark override, plus the switch, slider and button primitives both pages share. All state comes through `messaging.ts`; the pages never read storage or call the API.

**Popup states** (`data-state` on `<main>`): `done` — big count-up of sentences kept, "/ total", the ink-over-grey bone bar, "judged in 0.9 s · ≈ $0.0012" or "from cache", page-kind chip; `judging`/`idle` — the sentence total, pulsing, over "sentences, judging…" (it counts down to the kept number when the judgment lands), polled every 500 ms; `no-key` — "Osso needs your TypeSafe key." with a marrow "Add key"; `invalid-key` — key rejected, "Fix key"; `disabled` — "Off on this site" (or "Osso is off" when the master switch is off); `skipped` — "Nothing to strip here" + reason; `error` — the reason on one line + "Retry" (reloads the tab); `cannot` — "Osso can't run here" on chrome:// and store tabs, or "Osso is waking up" when the background never answers. Controls: the site switch (`setHostEnabled` then `setEnabledHere`), the strictness slider (`setThreshold` to the tab on input, `setSettings` on change), "Reveal all"/"Fade again".

**Options sections**: Key (show/hide, Test → "Works · 0.3 s" or the error inline, Save, privacy note), Behaviour (enabled, default strictness, reveal key, animations), Sites (never/always textareas saved on blur, collapsible default deny list), Usage (six figures, Clear cache, Reset usage), About. Every save shows an inline "Saved" that fades. Without a background the page renders the defaults and says so once under the masthead.

**Preview**: `npm run build`, open `chrome://extensions`, enable Developer mode, "Load unpacked" → `dist/`. Click the toolbar icon for the popup; right-click it → Options for the settings page (or `chrome-extension://<id>/options.html`). To see a state without a real page, open `chrome-extension://<id>/popup.html` in a tab and use the extension's service-worker console to seed a tab state. Unit tests: `npx vitest run test/ui.test.ts`.
